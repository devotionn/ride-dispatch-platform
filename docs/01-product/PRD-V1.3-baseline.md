# 打车接单与人工调度系统 — PRD V1.3 开发基线

- 文档状态：BASELINE
- 版本：V1.3
- 编制日期：2026-08-20
- 产品定位：小型车队人工调度 + 乘客轻量 H5 + 司机接单履约 + 收款结算
- 目标规模：司机约 300 人以内
- 当前说明：本文件把已提供的 PRD V1.3 内容整理为 Markdown 开发基线，尽量保持原有术语和业务边界；实现建议另见技术文档。

## 1. 项目概述

系统面向司机规模约 300 人以内的小型预约接送车队。实际运营由后台工作人员人工管理司机和人工派单，系统提供乘客下单、司机定向订单、公共订单池、附近司机筛选、履约状态、线上/线下收款、司机收入与提现、异常处理和审计能力。

产品边界：本项目不是大型全自动网约车平台。系统负责信息和流程，人负责调度判断。

## 2. 产品组成

| 端 | 使用者 | 核心职责 |
| --- | --- | --- |
| 乘客轻量 H5 | 乘客 | 公共/定向入口下单、A/B 点、订单状态、接单前取消、线上付款 |
| 司机 Android App | 司机 | 接单状态、位置、专属二维码、接受/拒绝、履约、收款、收入/提现 |
| PC 管理后台 | 管理员/调度/财务 | 司机管理、后台建单、附近司机、人工派单/改派、订单/支付/提现/审计 |
| 后端服务 | 系统 | 入口识别、订单状态机、定位、派单、支付、资金账本、品牌配置、日志 |

## 3. 平台品牌与 Logo 配置

- 公司名称：后台维护，各端读取展示。
- 公司 Logo / 品牌头像：后台上传，建议 PNG/JPG，按比例裁剪。
- 司机 App：登录页、首页顶部预留品牌位。
- PC 后台：登录页、菜单顶部或顶部导航预留品牌位。
- 乘客 H5：公共入口和司机定向入口建议展示平台 Logo/名称。
- 更换 Logo/公司名称优先动态读取，无需重新发布客户端。

## 4. 乘客 H5 入口体系

### 4.1 公共入口

- 固定 H5 URL 可直接访问。
- 可用于后续微信公众号菜单、官网、宣传二维码、分享链接或其他推广渠道。
- 进入时不携带司机标识，不默认指定司机。
- 提交后订单进入“待接单”，由后台人工调度。

### 4.2 司机专属二维码入口

- 每位司机一个长期有效二维码。
- 扫码后进入与公共入口相同的 H5，但自动携带并锁定对应司机。
- 乘客无需填写司机工号，也不能手工切换司机。
- 提交后进入“待司机确认”。
- 司机拒绝后解除原司机绑定，订单转入“待接单”，由后台继续派单。

### 4.3 推荐 URL 模型

| 入口 | 示例 | 业务含义 |
| --- | --- | --- |
| 公共入口 | `/ride` | 不绑定司机，提交后待接单 |
| 司机定向入口 | `/ride/d/{driverShortCode}` | 绑定指定司机，提交后待司机确认 |
| 付款入口 | `/pay/{orderPayToken}` | 绑定具体订单和金额，仅用于付款 |

## 5. 三种订单入口

| 来源 | 创建时是否绑定司机 | 创建后状态 | 后续 |
| --- | --- | --- | --- |
| 公共 H5 | 否 | 待接单 | 后台查附近司机并人工派单 |
| 司机专属二维码 H5 | 是 | 待司机确认 | 司机接受；拒绝后转待接单 |
| 后台代客创建 | 否 | 待接单 | 后台查附近司机并人工派单 |

## 6. 乘客 H5 下单

| 字段/元素 | 规则 |
| --- | --- |
| 平台品牌 | 显示公司 Logo/名称 |
| 指定司机信息 | 仅司机二维码入口展示，自动绑定且只读 |
| 出发地 A | 默认请求当前位置；可修改、搜索或地图选点；拒绝定位时手工输入 |
| 目的地 B | 搜索/地图选点 |
| 乘车人数 | 正整数 |
| 出发时间 | 日期 + 时间 |
| 手机号 | 直接输入，仅格式校验，不做短信验证码 |
| 备注 | 选填 |
| 提交 | 根据入口进入待接单或待司机确认 |

### 6.1 乘客可见订单状态

- 待接单
- 待司机确认
- 已接单
- 执行中
- 待付款
- 已完成
- 已取消 / 异常

### 6.2 乘客取消

- 司机接单前：乘客可自行取消。
- 司机接单后：乘客不能自行取消，需要联系后台。
- 后台对已接单/执行中订单可强制取消，但必须二次确认、填写原因并留审计日志。

## 7. 两类二维码严格分离

### 司机专属下单二维码

- 生命周期：长期有效，一个司机一个。
- 用途：绑定司机 + 进入下单 H5。
- 禁止：用于订单付款。

### 订单专属付款二维码

- 生命周期：每个订单进入收款阶段后生成。
- 用途：绑定订单 + 金额 + 支付上下文。
- 禁止：用于创建订单或绑定司机。

## 8. 司机 Android App

首期要求：

- 登录、个人/车辆资料、平台 Logo 展示。
- 可接单 / 暂停接单。
- 可接单状态下自动上报位置；超过 5 分钟未更新视为失效。
- 手工维护当前可接人数，不能超过车辆最大乘客数。
- 查看/展示个人长期专属二维码。
- 接收司机二维码订单、后台派单/改派订单。
- 新订单提醒：Android 系统通知 + 声音 + 震动。
- 接受/拒绝；拒绝必须选择快捷原因或“其他”。
- 允许同时执行多个订单，顺路与否由司机自行判断。
- 按顺序推进：到达出发地、接到乘客、行程中、到达目的地。
- 录入线下协商金额；选择微信、支付宝或线下收款。
- 查看收入、可提现金额、提现记录，提交提现申请。

## 9. 附近司机与人工派单

| 规则 | V1.3 口径 |
| --- | --- |
| 中心点 | 订单 A 点 |
| 范围 | 10km 内 |
| 司机账号 | 正常 |
| 接单状态 | 可接单 |
| 位置有效 | 最近更新 ≤ 5 分钟 |
| 人数 | 当前可接人数 ≥ 订单人数 |
| 排序 | 直线距离从近到远 |
| 最终决策 | 后台调度员人工选择，不自动派单 |

10km 内没有合适司机时，后台仍可进入全部可接司机列表人工选择，避免系统阻断实际调度。

## 10. 派单、拒单与改派

- 后台派单后订单进入“待司机确认”。
- 后台显示“待确认多久”，不自动取消、不自动改派。
- 司机拒绝时必须选择原因，订单回到“待接单”。
- 未执行订单后台可直接改派。
- 已接单/执行中订单允许强制改派，但必须二次确认、填写原因、保存原司机/新司机和审计日志。

## 11. 履约状态机

| 状态 | 说明 |
| --- | --- |
| 待接单 | 未指定司机，等待后台调度 |
| 待司机确认 | 已指定目标司机，等待接受/拒绝 |
| 已接单 | 司机已接受 |
| 执行中 | 到达、接客、运输等履约中 |
| 待付款 | 到达目的地并确认金额，等待付款 |
| 已完成 | 线上支付成功或线下收款确认 |
| 已取消 | 按乘客/后台权限取消 |
| 异常 | 人工处理的特殊订单 |

司机拒绝是一次派单尝试，不是订单终态；拒绝后订单重新进入待接单。

## 12. 价格与支付

系统不自动计价。价格由司机与乘客线下协商，司机在收款前录入最终金额。

### 12.1 微信 / 支付宝

1. 司机到达目的地并录入最终金额。
2. 系统生成该订单专属付款二维码。
3. 乘客扫码进入订单付款页，完成微信或支付宝支付。
4. 支付结果以支付平台服务端回调为准。
5. 支付成功后保存第三方流水号、金额和时间，订单进入已完成。

### 12.2 线下收款

- 司机选择“线下收款”，确认已收到对应金额。
- 系统二次确认后完成订单。
- 后台可修正线下收款记录，但必须填写原因、二次确认并保留修改前后审计。

## 13. 线上商户收款与司机提现

资金路径：

```text
乘客微信/支付宝付款
→ 甲方公司对应商户账户
→ 按支付平台结算规则进入甲方结算银行卡
→ 系统记入对应司机业务收入
→ 司机申请提现
→ 后台审核
→ T+3 人工打款
```

规则：

- 首期平台抽佣为 0。
- 系统可提现余额是业务账本，不等于银行账户实时余额。
- 首期提现收款方式可录入银行卡、微信、支付宝信息。
- 不接自动代付 API，后台人工转账。
- 提现状态：待审核 → 审核通过/待打款 → 已打款；另有已驳回。
- 审核通过后默认 T+3 完成人工打款，记录审核人、打款人、计划/实际打款时间。

## 14. PC 管理后台

### 14.1 品牌与系统设置

- 公司名称配置。
- Logo/头像上传与替换。
- 后台、司机 App、乘客 H5 读取统一品牌配置。

### 14.2 司机管理

- 新增/编辑/启用/停用司机。
- 工号、手机号、车辆、最大载客人数。
- 可接单状态、当前可接人数、最近位置、位置更新时间。
- 司机专属二维码查看/导出。
- 当前订单、历史订单、完成订单数、收入与提现记录。

### 14.3 订单与调度

- 全部订单及按状态筛选。
- 区分公共 H5、司机二维码、后台代客三种来源。
- 后台代客创建订单。
- A 点 10km 内附近司机列表、距离排序、人工派单。
- 待确认时长、拒绝原因、改派、强制改派。
- 取消、执行中强制取消、异常处理、操作时间线。

### 14.4 财务与提现

- 微信、支付宝、线下收款记录。
- 司机收入流水、可提现余额。
- 提现申请审核、驳回、待打款、已打款。
- 线下收款人工修正及审计。

## 15. UI 页面清单

### 乘客 H5

公共首页/下单页、司机定向下单页、订单确认、状态页、取消确认、付款页、支付结果；顶部展示平台 Logo/名称。

### 司机 App

登录、工作台、平台 Logo、专属二维码、待确认、执行中、历史、订单详情、拒绝原因、可接人数、位置状态、价格/收款、收入/提现、个人资料。

### PC 后台

登录、品牌 Logo、首页、系统品牌配置、司机管理、二维码管理、全部订单、后台建单、附近司机、派单/改派、异常、支付、收入、提现、操作日志。

## 16. 取消与退款

| 场景 | 规则 |
| --- | --- |
| 乘客在司机接单前 | 可自行取消 |
| 乘客在司机接单后 | 不能自行取消，联系后台 |
| 后台未接单订单 | 可取消 |
| 后台已接单/执行中 | 可强制取消；二次确认 + 必填原因 + 审计日志 |
| 已支付订单退款 | V1.3 不做自动退款；进入人工异常处理并留记录 |

## 17. 权限与审计

- 后台是人工运营控制中心，拥有较高权限。
- 执行中改派、执行中强制取消、线下收款修正、提现审核/打款等必须完整留痕。
- 微信/支付宝支付成功状态不得由后台人工伪造，以第三方支付回调为准。
- 重要日志至少保存：操作人、对象、动作、修改前、修改后、时间、原因/备注。

## 18. 核心数据对象

- `PlatformBrand`：公司名称、Logo 地址、更新时间。
- `Driver`：ID、工号、姓名、手机号、状态、接单状态、车辆、最大人数、可接人数、二维码短码、经纬度、定位时间。
- `Order`：订单号、入口来源、目标/当前司机、乘客手机号、A/B 点及经纬度、人数、时间、金额、状态、支付方式、创建/完成时间。
- `DispatchAttempt`：订单、司机、派单人、派单时间、接受/拒绝时间、拒绝原因、改派信息。
- `Payment`：支付单号、订单号、支付方式、金额、状态、第三方流水、支付时间。
- `DriverLedger`：司机、订单、收入金额、余额变化、时间。
- `Withdrawal`：司机、金额、收款方式、账号、状态、审核/计划/实际打款时间、操作人。
- `OperationLog`：操作人、对象、动作、前后值、时间、原因。

## 19. 首期明确不做

- 微信公众号本身的申请、认证、菜单开发和公众号用户体系；公共 H5 需支持后续挂载。
- 乘客原生 App。
- 乘客复杂账号注册、短信验证码登录、会员中心。
- 自动派单、AI 派单、抢单大厅。
- 顺路算法、路线智能匹配。
- 驾车导航、语音导航、实时轨迹、实时路况。
- 自动计价、动态计价、预估价。
- 司机/乘客 IM、网络电话。
- 自动代付 API。
- 自动退款接口。
- 优惠券、积分、会员、评价、发票等非核心营销功能。

## 20. 验收标准

### 20.1 乘客 H5

- 公共 URL 可直接打开下单页，不依赖司机二维码。
- 公共入口提交订单后进入待接单。
- 司机专属二维码入口正确绑定指定司机，提交后进入待司机确认。
- A 点默认尝试当前位置；拒绝定位仍可手工填写，且始终可修改。
- 手机号无需验证码即可下单。
- 接单前乘客可取消。
- 到达目的地后可通过订单专属付款二维码完成微信/支付宝付款。

### 20.2 司机 App

- 登录页/首页展示后台配置的平台 Logo/名称。
- 司机专属二维码长期有效并正确打开定向 H5。
- 定位超过 5 分钟未更新后不进入附近候选。
- 新单有系统通知 + 声音 + 震动。
- 接受/拒绝流程正确，拒绝后订单进入待接单。
- 多订单可并存，顺路由司机判断。
- 履约步骤按顺序推进。
- 收款和提现流程可完成。

### 20.3 PC 后台

- 可配置公司 Logo/名称，并在后台、司机端、乘客 H5 正确展示。
- 可区分三种订单来源。
- 可后台代客建单。
- 可查询 A 点 10km 内有效附近司机并按距离排序。
- 可人工派单，显示待确认时长，不自动改派。
- 执行中可强制改派/取消，必须二次确认、原因和日志。
- 可管理支付、司机收入、提现及 T+3 人工打款。

## 21. 最终业务闭环

### 公共推广订单

```text
公众号菜单/官网/推广二维码/分享链接
→ 公共 H5
→ 乘客下单
→ 待接单
→ 后台查 10km 附近司机
→ 人工派单
→ 司机确认
→ 履约
→ 订单付款二维码/线下收款
→ 完成
```

### 司机定向订单

```text
司机专属二维码
→ H5 自动绑定司机
→ 乘客下单
→ 待司机确认
→ 接受则履约
→ 拒绝则转待接单
→ 后台继续派单
```

### 后台代客订单

```text
后台创建
→ 待接单
→ 附近司机
→ 人工派单
→ 履约
→ 收款
→ 完成
```

## 22. 产品结论

V1.3 将乘客 H5 设计为独立公共入口，同时保留司机定向二维码；司机二维码与订单付款二维码严格分离；PC 后台、司机 App 和乘客 H5 从首期共享统一品牌配置。
