本文件是当前项目的功能状态单一基线，区分“已完成并通过本地验证”“仍可在本地继续开发”“依赖真实外部条件”“PRD 首期明确不做”四类事项。后续开发必须优先处理本文件中的 P0/P1 项，避免把 Mock、本地环境或模拟器结果误报为生产完成。

## 3. 已完成功能

### 3.1 订单与调度

- 公共 H5、司机定向 H5、后台代客三种订单入口。
- 乘客 A/B 点、人数、时间、手机号、备注、订单 Token 和接单前取消。
- 附近司机 10km、位置 5 分钟时效、可接人数过滤、距离排序。
- 人工派单、拒单回待接单、待确认时长、改派、强制改派、强制取消、异常标记。
- 四阶段履约、最终金额锁定和订单进度时间线。

### 3.2 支付、账务与异常

- Mock 微信/支付宝支付、失败重试、金额校验、重复回调幂等。
- 线下收款二次确认、业务收入入账且不重复增加可提现余额。
- 司机收入、可提现余额、提现冻结、财务审核/驳回/人工打款。
- 线下支付追加式纠偏，支付异常登记/解决/驳回，操作审计。
- 支付尝试、提现、支付异常的幂等键和冲突校验。

### 3.3 三端产品

- Admin：登录、品牌 URL 配置、司机管理、订单调度、支付、退款异常、提现、操作日志、报表导出。
- Passenger H5：下单、状态、取消、付款页、Mock 支付二维码和元金额展示。
- Driver Android：登录、工作状态、位置上报、派单提醒、接受/拒绝、履约、金额、线下收款、收入、提现、历史订单和司机资料。

## 4. 仍可本地继续开发的事项

这些事项不是 PRD 首期排除项，可以在没有云服务器、真实支付商户或真机的情况下继续完成。

### P0：PRD 完整性缺口

1. **Logo 文件上传与替换** — **已完成（本轮）**
   - 已增加管理员上传接口、PNG/JPEG/WebP 文件头与大小校验、受控本地存储、公开读取 URL 和审计。

2. **司机二维码图片展示与导出** — **已完成（本轮）**
   - 已增加服务端 PNG 生成、Admin 预览/下载、Android 预览，并保持司机下单二维码与付款二维码严格分离。

3. **司机详情统计** — **已完成（本轮）**
   - 已增加当前订单、历史订单、完成订单数、业务收入、可提现余额、提现记录的只读聚合查询和后台详情展示。

### P1：产品可靠性与运维能力

4. **实时事件与通知抽象** — **本地实现已完成，动态事件专项回归与厂商 Push 仍待补测**
   - 已增加司机权限边界内的 SSE 事件接口和提交后发布的派单/状态事件。
   - Android 后台服务已接入 SSE、指数退避重连和事件触发状态刷新；15 秒轮询继续作为降级通道，最终业务仍以服务端状态为准。SSE 连接/解析和构建已验证，完整“派单→事件→通知”模拟器回归仍应补做。
   - PushProvider、厂商 Push 和锁屏/省电专项验收仍待补齐。

5. **弱网与恢复能力**
   - Android 已增加 GET 请求有限次数退避重试、SSE 断线指数重连、请求状态恢复和重复提交保护。
   - 增加服务端并发、断连、重复回调和恢复后的自动化测试。

6. **本地生产化部署包** — **数据库备份/恢复入口已完成，服务硬化仍进行中**
   - 已增加 MySQL 备份/恢复脚本、显式恢复确认和部署说明；已在临时恢复库验证 10 个 Flyway 版本可恢复。
   - 后端 + MySQL + Nginx 一体化 Compose、日志脱敏、限流、密钥校验和告警仍待后续 P1 任务。

7. **支付 Provider 与对账前置模型**
   - 在不接真实商户的前提下，抽象微信/支付宝 Provider、回调验签边界、主动查询接口和差异单模型。
   - Mock Provider 继续作为本地默认实现。

- 真实银行/第三方钱包打款、财务机构回单和真实退款执行。
- 生产域名、HTTPS、云服务器公网访问、正式备份和灰度发布。
- 高德真实 Key 下的地图搜索/定位专项验收。
- Android 真机的锁屏、厂商省电、后台定位、Push 和弱网验收。

- 自动派单、AI 派单、抢单大厅、顺路算法和路线智能匹配。
- 驾车导航、语音导航、实时轨迹和实时路况。
- 自动计价、动态计价和预估价。
- 司机/乘客 IM、网络电话。
- 自动代付、自动退款。
- 优惠券、积分、会员、评价、发票等非核心营销能力。

## 7. 开发顺序与完成定义

执行顺序固定为：

1. P0 Logo 上传与二维码图片能力。
2. P0 司机详情统计。
3. P1 实时事件与通知降级。
4. P1 弱网/恢复测试和部署硬化。
5. P1 支付 Provider/对账前置模型。

每项完成必须同时满足：后端接口、前端/Android 使用面、权限校验、审计或安全边界、自动化测试、构建通过，并更新本文件状态。
